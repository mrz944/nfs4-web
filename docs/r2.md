# Hosting the game files on Cloudflare R2

By default `node web/serve.mjs --game game` sends the game files from your machine, through the
tunnel, to every new player (about 442 MB each). With R2 the page and the lobby stay on your
machine, but the big download comes from Cloudflare's storage instead:

- your upload bandwidth isn't used for downloads;
- the download is 347 MB (gzip) and holds only the original VEG files, no macOS leftovers;
- a broken download resumes where it stopped (per 32 MB chunk) instead of starting over;
- R2 has no egress fees; storage is about 0.35 GB, inside the free tier (10 GB).

## 1. Pack the game files

Pack the untouched VEG release (base_eng + patch beta), not your own `game/` folder, which has
your saves, ghosts and settings in it:

```sh
node tools/pack-game.mjs build/veg/game build/r2
```

This writes `build/r2/<id>/`: `index.json` plus `chunk-000.gz` … `chunk-012.gz`. The `<id>` is a
hash of the content, so a changed game folder gets a new folder and old players' caches never
mix with new files. It also checks that `nfs3.exe` matches the current web build.

## 2. Create the bucket and a public domain

In the Cloudflare dashboard → **R2** → **Create bucket** (for example `nfs3-files`).

Then **Settings** → **Custom Domains** → **Connect domain**: `r2.nfs3.xyz`. Use a custom
domain, not the `r2.dev` address, which is rate limited and meant for testing only.

## 3. CORS

The page runs cross-origin isolated (COEP `require-corp`), so files from another origin need
CORS. Bucket → **Settings** → **CORS policy**:

```json
[
  {
    "AllowedOrigins": ["https://nfs3.xyz", "http://localhost:8080"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "MaxAgeSeconds": 86400
  }
]
```

## 4. Upload

```sh
npx wrangler login                                   # once
tools/r2-upload.sh nfs3-files build/r2/<id>          # uploads to nfs3/<id>/
```

Any S3 tool works too (rclone, `aws s3 cp` with the R2 endpoint). Two rules: **no**
`Content-Encoding` header (the page unpacks the gzip itself), and upload `index.json` last.

## 5. Point the page at it

```sh
cp web/game-source.json.example web/game-source.json   # then put your <id> in the URL
```

```json
{ "url": "https://r2.nfs3.xyz/nfs3/<id>/" }
```

`web/game-source.json` is git-ignored. When it exists, new players download from R2, and the
server no longer needs `--game` (keeping it is harmless: the pack is tried first). Players who
already have the game in their browser keep it.

Check it from a terminal:

```sh
curl -sI -H 'Origin: https://nfs3.xyz' https://r2.nfs3.xyz/nfs3/<id>/index.json | grep -i access-control
```

## Updating the game files

Run `pack-game.mjs` again, upload the new `<id>` folder and change the URL in
`game-source.json`. Browsers that have the old pack keep playing with it until they press
**Forget game files**. Delete old `<id>` folders from the bucket once nobody needs them.
