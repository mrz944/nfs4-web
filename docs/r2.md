The public site uses folder import until a pack is uploaded and `web/game-source.json` is
configured. The R2 downloader uses the same pack format as NFS3 Web.

# Hosting the game files on Cloudflare R2

With `node web/serve.mjs --game game`, game files come from your machine, through the
tunnel, to every new player. With R2 the page and the lobby stay on your
machine, but the big download comes from Cloudflare's storage instead:

- your upload bandwidth isn't used for downloads;
- the download is gzip-compressed and holds clean CD data plus the Modern Patch beta;
- a broken download resumes where it stopped (per 32 MB chunk) instead of starting over;
- each pack has its own content-derived URL and immutable cache headers.

## 1. Pack the game files

Stage the original CD's DATA and SAVEDATA with the Modern Patch beta overlaid, merging paths
case-insensitively. Use clean source files rather than local saves or edited settings. The
prepared staging directory is `build/r2-source/`:

```sh
node tools/pack-game.mjs build/r2-source build/r2-packs
```

This writes `build/r2-packs/<id>/`: `index.json` plus `chunk-*.gz`. The `<id>` is a
hash of the content, so a changed game folder gets a new folder and old players' caches never
mix with new files. Confirm that the reported `nfs4.exe` hash matches `web/dist/build-info.json`
before uploading; the browser rejects mismatched packs. `build/r2/` already contains native
test artifacts, so use the separate `build/r2-packs/` directory for packs.

## 2. Create the bucket and a public domain

In the Cloudflare account containing nfs4.xyz, go to **R2** → **Create bucket**
(for example `nfs4-files`).

Then **Settings** → **Custom Domains** → **Connect domain**: `r2.nfs4.xyz`. Use a custom
domain for the public download URL.

## 3. CORS

The page runs cross-origin isolated (COEP `require-corp`), so files from another origin need
CORS. Bucket → **Settings** → **CORS policy**:

```json
[
  {
    "AllowedOrigins": ["https://nfs4.xyz", "http://localhost:8084", "http://localhost:8080"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "MaxAgeSeconds": 86400
  }
]
```

## 4. Upload

```sh
npx wrangler login                                # use the account with the bucket
tools/r2-upload.sh nfs4-files build/r2-packs/<id>    # uploads to nfs4/<id>/
```

Any S3 tool works too (rclone, `aws s3 cp` with the R2 endpoint). Two rules: **no**
`Content-Encoding` header (the page unpacks the gzip itself), and upload `index.json` last.

## 5. Verify the upload and point the page at it

Before enabling downloads, verify that `index.json` and every chunk return HTTP 200 from
the public domain, with an `Access-Control-Allow-Origin` header for `https://nfs4.xyz`.
Chunks must have the byte sizes in the index and no `Content-Encoding` header.

```sh
cp web/game-source.json.example web/game-source.json   # then put your <id> in the URL
```

```json
{ "url": "https://r2.nfs4.xyz/nfs4/<id>/" }
```

`web/game-source.json` is git-ignored. When it exists, new players download from R2, and the
server no longer needs `--game` (keeping it is harmless: the pack is tried first). Players who
already have the game in their browser keep it.

Check it from a terminal:

```sh
curl -sI -H 'Origin: https://nfs4.xyz' https://r2.nfs4.xyz/nfs4/<id>/index.json | grep -i access-control
```

## Updating the game files

Run `pack-game.mjs` again, upload the new `<id>` folder and change the URL in
`game-source.json`. Browsers that have the old pack keep playing with it until they press
**Forget game files**. Delete old `<id>` folders from the bucket once nobody needs them.
